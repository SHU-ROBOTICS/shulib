- 01:35:00 — THE DESIGN FORK, decided: **EAGER fluent chain** (each step executes as it is chained), NOT deferred. The deciding arguments, in order of weight:
  1. The first-year readability test. Eager: a routine reads top-to-bottom and runs top-to-bottom. Deferred: `chain.moveTo(a); chassis.turnTo(b); chain.run();` runs b BEFORE a — mixed-tier code would read one way and run another, which is the exact confusion class Tier 2 exists to kill, and mixed-tier usage is a hard requirement (no cliff).
  2. Constraint 4 (errors must not vanish): eager lets the chain ACT on a failure the moment it happens — stop, skip the rest, put the drive in the safe state via cancel(). The robot's behaviour carries the error even if the author never reads the result.
  3. Deferred needs step storage → type-erased callables → heap or an arbitrary fixed capacity, plus the worst misuse door of all: a chain built but never .run() — compiles, runs, robot does NOTHING.
  4. The G2/F2 "seam" argument for deferred is weaker than it looks: G2's PathRunner consumes DATA (waypoints+markers), F2's combinators live at the scheduler; neither wants the recipe layer's step list. Making the recipe chain their engine would put sequencing logic in a layer that must delegate only.
  Full rejected-alternative analysis goes in D1-COMPLETED (the standard).
- 01:35:40 — Chain error policy decided: STOP at first failure + SAFE (cancel() ⇒ 0V+Brake) + SKIP the rest (counted, logged) + REPORT (RoutineResult{stoppedAt, name, cause, exit} + Warn line). Rationale: generalizes C4 D8's followTrajectory stop-on-first-failure to the whole routine; "chasing later waypoints on a lie compounds blindly".
